## Section A: Explicit Product Owner Decisions

### DEC-001: Product Identity & Focus
- **Topic:** Product Scope & Proposition
- **Decision:** The product is named **Agri**. It is a mandi price intelligence and short-term forecasting platform for Indian farmers, traders, and price evaluators.
- **Owner Reasoning:** Help farmers make informed harvesting and selling decisions before transporting crops to market. The primary differentiator is 14-day price forecasting combined with nationwide market discovery.
- **Consequences:** All features must serve price transparency and comparison. Agronomic features (crop/fertilizer recommendations) are explicitly rejected.
- **Implementation Status:** `[IMPLEMENTED, VERIFIED]`
- **Requires Owner Approval:** Yes `[REQUIRES OWNER APPROVAL]`

---

### DEC-002: Nationwide Mandi Coverage Scope
- **Topic:** Geography Dataset Migration
- **Decision:** Ingest all **2,617 unique mandis** across **30 Indian states and union territories** and 500+ districts from `ALL_CROPS_DATA.csv` and `hierarchy_map.csv`, replacing the prototype 29-mandi seed.
- **Owner Reasoning:** Agri must represent the complete national agricultural landscape, not an isolated demo sandbox.
- **Consequences:** 2,643 physical entities ingested (28 legitimate cross-state homonyms preserved with state-prefixed canonical slugs). Database indexes and frontend pagination required to maintain high responsiveness.
- **Implementation Status:** `[IMPLEMENTED, VERIFIED]`
- **Requires Owner Approval:** Yes `[REQUIRES OWNER APPROVAL]`

---

### DEC-003: Strict Zero Coordinate Fabrication Policy
- **Topic:** Geocoding & Coordinate Integrity
- **Decision:** Never fabricate, hallucinate, or collapse missing GPS coordinates onto district centroids. Mandis without exact GPS coordinates must have `latitude = NULL`, `longitude = NULL`, and `coordinate_status = 'UNRESOLVED'`.
- **Owner Reasoning:** Displaying fake map pins or incorrect road distances damages farmer trust and causes real-world logistical confusion.
- **Consequences:** 151 mandis with verified coordinates display map markers. 2,492 mandis without coordinates remain 100% discoverable and searchable in list views with an explicit `Coordinates Pending` badge. Map layer filters nulls without crashing.
- **Implementation Status:** `[IMPLEMENTED, VERIFIED]`
- **Requires Owner Approval:** Yes `[REQUIRES OWNER APPROVAL]`

---

### DEC-004: Prediction History vs. Historical Prices Separation
- **Topic:** Data Semantics & Ground Truth
- **Decision:** Maintain a strict, unambiguous separation between **Historical Prices** (actual physical APMC market transactions) and **Prediction History** (previous forecast runs generated by the ML model).
- **Owner Reasoning:** Conflating predictions with actual ground truth produces misleading analytics and violates scientific reporting standards.
- **Consequences:** Separate database tables (`price_observations` vs `forecast_runs`). Separate UI views (`/market/:id` historical charts vs `/prediction-history` audit inspect modal). Empty states remain authentic without fake pre-populated runs.
- **Implementation Status:** `[IMPLEMENTED, VERIFIED]`
- **Requires Owner Approval:** Yes `[REQUIRES OWNER APPROVAL]`

---

### DEC-005: Location Precedence & Privacy
- **Topic:** Geolocation & Privacy
- **Decision:** Location precedence strictly: (1) Explicit browser geolocation with user permission, (2) User manual selection via dynamic modal, (3) Saved local storage location. Never default silently to Bangalore. Do not persist coordinates to backend databases.
- **Owner Reasoning:** Respect farmer privacy while ensuring user-selected locations are never arbitrarily overwritten.
- **Consequences:** Clean HTML5 Geolocation prompt with non-intrusive manual fallback (`State` ➔ `District` ➔ `Mandi`).
- **Implementation Status:** `[IMPLEMENTED, VERIFIED]`
- **Requires Owner Approval:** Yes `[REQUIRES OWNER APPROVAL]`

---

### DEC-006: 14-Day Fixed Evaluation Reference Date Contract
- **Topic:** Prototype Forecasting Contract
- **Decision:** Evaluation reference date fixed at `2026-11-23`. Future forecast horizon strictly spans `2026-11-24` to `2026-12-07` inclusive (exactly 14 daily points).
- **Owner Reasoning:** Anchors evaluation to the latest validated historical training period in the research dataset, allowing standardized testing and model verification.
- **Consequences:** Spring Boot backend orchestrates reference date; Python model outputs exactly 14 daily predictions with expanding uncertainty bands. Connected chart visually bridges on 23 Nov.
- **Implementation Status:** `[IMPLEMENTED, VERIFIED]`
- **Requires Owner Approval:** Yes `[REQUIRES OWNER APPROVAL]`

### DEC-007: Zero-Authentication Saved Markets
- **Topic:** User Accounts & Watchlists
- **Decision:** No login, registration, password, or SMS OTP required. Saved markets are stored purely in client-side `localStorage`.
- **Owner Reasoning:** Eliminates onboarding friction for farmers who want immediate access without account credentials.
- **Consequences:** Instant bookmarking; persists across reloads; zero user database overhead.
- **Implementation Status:** `[IMPLEMENTED, VERIFIED]`
- **Requires Owner Approval:** Yes `[REQUIRES OWNER APPROVAL]`

---

### DEC-008: Sliding-Window Rate Limiting
- **Topic:** API Protection & DoS Prevention
- **Decision:** Mandatory sliding-window rate limiter on all public backend APIs by client IP, returning standard HTTP 429 and rate-limit headers. Exempt health checks.
- **Owner Reasoning:** Protects inference service and database from malicious traffic or runaway scraping scripts.
- **Consequences:** Redis-backed Lua implementation for multi-instance production; in-memory sliding window fallback for local development. Verified across unit tests and live API suite.
- **Implementation Status:** `[IMPLEMENTED, VERIFIED]`
- **Requires Owner Approval:** Yes `[REQUIRES OWNER APPROVAL]`

---

### DEC-009: Deployment Option A (Vercel + Single VPS)
- **Topic:** Infrastructure Architecture
- **Decision:** Next.js frontend deployed to Vercel; Java Spring Boot, Python FastAPI, PostgreSQL, and Redis hosted via Docker Compose on a single Ubuntu VPS (approx 2 vCPU, 4 GB RAM, 40-60 GB SSD) with reverse proxy (Nginx/Caddy). No Kubernetes.
- **Owner Reasoning:** Highly cost-effective, easy to monitor, low operational complexity, sufficient for national prototype evaluators.
- **Consequences:** Single compose file with private networking for PostgreSQL, Redis, and Python inference service; only Nginx and Java public endpoints exposed.
- **Implementation Status:** `[IMPLEMENTED, VERIFIED]`
- **Requires Owner Approval:** Yes `[REQUIRES OWNER APPROVAL]`

## Section B: Technical Recommendations Accepted by Owner

### REC-001: State-Prefixed Slug Canonical IDs
- **Recommendation:** Use state-prefixed slugs (e.g. `pb-adampur-apmc` vs `hr-adampur-apmc`) to resolve 28 legitimate cross-state mandi homonyms.
- **Outcome:** Accepted. Preserves 100% of physical mandi entities without collisions.
- **Implementation Status:** `[IMPLEMENTED, VERIFIED]`

### REC-002: PostgreSQL COPY Expert Ingestion
- **Recommendation:** Use PostgreSQL binary streaming `COPY` with temporary index drops to ingest 1.136M records in under 20 seconds.
- **Outcome:** Accepted. Ingestion completed in 15.75s with zero record truncation.
- **Implementation Status:** `[IMPLEMENTED, VERIFIED]`

### REC-003: Autoregressive Feature Alignment for LightGBM
- **Recommendation:** Dynamically construct all 69 lag, rolling, cyclical, weather, and categorical features expected by the LightGBM booster artifact to prevent flat-line predictions.
- **Outcome:** Accepted. Forecast curves reflect non-flat market dynamics with bounded uncertainty bands.
- **Implementation Status:** `[IMPLEMENTED, VERIFIED]`
